# Channel Health, Mirrors, and Maintenance Automation Design

Date: 2026-08-01

## Objective

Improve long-term maintenance with auditable 100-point health scores, actual
GitHub Raw/jsDelivr equality checks, generated favorites, and a read-only EPG
discovery scaffold. Do not expand the channel catalog or weaken provenance and
HLS validation.

## Compatibility contract

- Keep root `news.m3u` and `playlists/news.m3u` unchanged and byte-identical.
- Keep every existing Raw URL documented and operational.
- Keep all ten stream URLs and their existing full `tvg-id` values unchanged.
- Keep the `Check news streams` workflow, 04:00 Beijing schedule,
  `workflow_dispatch`, existing `stream-health-report` artifact, and strict
  failure propagation.
- Keep generating `reports/stream-report.md`; add
  `reports/health-report.md` without removing the old report path.
- Scores are informational and never edit or remove playlist entries.

## Health score

The current five-star rating remains available for compatibility. A new
0–100 score is calculated independently from explicit validation evidence:

| Dimension | Maximum |
|---|---:|
| Initial HTTP access | 15 |
| HLS master manifest | 15 |
| Variant playlist discovery | 15 |
| First media segment | 20 |
| Resolution | 15 |
| Total probe latency | 15 |
| Redirect count | 5 |

Resolution awards 15 points at 1080p or above, 12 at 720p, 6 at 480p, and zero
when lower or unknown. Latency awards 15 points at or below 1 second, 12 through
3 seconds, 8 through 5 seconds, 4 through 10 seconds, and zero above 10 seconds.
Redirects award 5, 4, 3, 1, or 0 points for zero, one, two, three, or more than
three redirects.

`Healthy` means a passed check scoring at least 90. `Degraded` means a passed
check scoring 75–89. Any failed check, or a score below 75, is `Unhealthy`.
The existing process exit code remains based only on strict HLS success.

The Markdown report includes detection status, health status, score out of 100,
five-star rating, resolution/bitrate, HTTP, master/variant/segment evidence,
latency, redirects, and failure details.

## Mirror validation

`scripts/check_mirrors.py` downloads the existing root GitHub Raw URL and the new
jsDelivr URL with a bounded timeout and project User-Agent. It computes SHA-256
over the exact response bytes and exits nonzero for HTTP errors, timeouts, or a
mismatch. It does not rewrite either playlist.

Deterministic unit tests use a local HTTP server for matching and mismatching
payloads. GitHub Actions performs the real remote check daily after stream
validation. A mirror failure is propagated after the existing report artifacts
are uploaded.

## Generated favorites

`config/favorites.yaml` uses a deliberately strict YAML subset: one `favorites`
key followed by an ordered list of exact full `tvg-id` values. No aliases, URLs,
or additional keys are accepted.

`scripts/generate_favorites.py` parses the canonical playlist, requires every ID
to exist exactly once, preserves configuration order, and renders entries using
only metadata and stream URLs already present in the main playlist. Missing or
duplicate IDs fail. Normal mode writes `playlists/favorites.m3u`; `--check` mode
compares generated bytes with the committed file and never writes.

Actions runs `--check`, so configuration drift fails visibly but automation does
not modify the repository.

## EPG discovery scaffold

`scripts/discover_epg.py` accepts one or more exact full `tvg-id` values and
validates them against `playlists/news.m3u`. It prints deterministic JSON records.
The candidate registry is intentionally empty in this release, producing
`status: no-confirmed-source` and `candidates: []`.

The script performs no network access and has no write path. It cannot modify
`epg/epg.xml` or fabricate programmes. Future candidates must be added through
source review before any separate importer is considered.

## Workflow and reports

The existing workflow entry points remain unchanged. New maintenance checks run
with `continue-on-error` so both `reports/health-report.md` and the legacy
`reports/stream-report.md` can be uploaded even when a stream, mirror, or generated
favorites check fails. A final propagation step fails the job when any strict
check failed. No step commits, pushes, replaces a channel, or edits EPG data.

## Testing and release verification

Tests are written first for score boundaries and report fields, mirror SHA logic,
strict YAML parsing and order, unknown/duplicate favorite IDs, generated-file
equality, EPG ID mapping, discovery read-only behavior, and workflow compatibility.

Release verification runs the complete suite with warnings treated as errors,
regenerates and checks Favorites, probes all ten live HLS sources, compares the
two real remote playlist URLs after push, runs the workflow manually, and verifies
the remote commit and Raw compatibility URLs.
